## 1. 起動方法

UI もランチャも無い。**実起動パスは `tools/voice_chat.py` の1本のみ**。

```powershell
cd <リポジトリのルート>
$env:PYTHONIOENCODING="utf-8"
& .\.venv\Scripts\python.exe tools\voice_chat.py
# Ctrl+C で終了（全サイドカーを drain して停止）
```

### 前提
- **セットアップ**: `python -m venv .venv` → `.\.venv\Scripts\pip install -r requirements.txt`
  **2026-08-08 に v2 専用 `.venv` を実際に作成済**（Python 3.13.3 / torch 2.13.0+cpu / winsdk）。
  それ以前は前作（`../portfolio8-VLM-AI/venv`）を流用していた。torch は CPU 版で入れる:
  `pip install torch --index-url https://download.pytorch.org/whl/cpu`。
  文字ゲート（`VLM_OCR_ENABLED=1`）を使うなら `pip install winsdk` と OCR 言語パック(ja) が要る。
- **VOICEVOX 起動必須**（`http://127.0.0.1:50021`）。未起動でも落ちないが声が出ない。確認 `curl -s http://127.0.0.1:50021/version`
- **マイク + イヤホン**（AEC は不採用＝スピーカーだと自分の声を拾う）
- **`.env` が必要**（`.env.example` をコピーして API キーを入れる）
- 初回のみネットワーク: Silero VAD（torch.hub キャッシュ）/ Ruri 埋め込み（HuggingFace DL）

### 起動ログで機能の有効/無効を必ず確認する
```
Call-Function 稼働（read-only 能力）        ← CALLFUNCTION_ENABLED=1
タスク管理 稼働（予約タスク）                ← TASK_ENABLED=1
Web検索 稼働（search_web・TaskAgent 専用）   ← SEARCH_ENABLED=1 かつ ddgs 導入済
作業フォルダ 稼働（C:\eve_ws\workspace・…）  ← WS_ENABLED=1
プログラム実行 稼働（run_program・…）        ← WS_EXEC_ENABLED=1 かつ setup_sandbox.py apply 済
画面表示 稼働（show_on_screen・別ウィンドウ） ← WS_VIEWER_ENABLED=1
画面認識(VLM) 稼働                          ← VLM_ENABLED=1
VoiceLoop 稼働。話しかけてください。
```
**この行が出ていない機能は動いていない。** `Config` は `VoiceLoop()` 構築時に1回だけ読むので `.env` 変更は再起動が必要。
**search / 作業フォルダは TASK_ENABLED の内側**でしか生成されない（単独で 1 にしても無効）。

#### UI 前提工事（2026-08-14・`docs/UI_DESIGN.md` P2）

メニューの ON/OFF を作る**前**に必要な2つの原始的な欠落を埋めた。**まだ本番の呼び出し元は
無い**（消費者は P4 のメニュー実装）。テストからは呼んでおり死にコードではない。

1. **サイドカーが再開できなかった**: 全 stop() が `_stopping = True` を立てたままで、
   `start()` しても新しい run ループが最初の `while not self._stopping` で即座に抜けていた。
   → 該当 **9クラス全部**の `start()` で `_stopping = False` に戻す
   （FeedbackWorker / DeliveryChecker / FunctionDispatcher / SpeechDecider / SilenceMonitor /
   CancelResolver / TaskExecutor / ReconcileTimer / VlmWorker）。
   - `_stopping` は `__init__` / `stop()` / run ループの中でしか読まれない（grep 全件確認）ので、

#### 文字ゲート（実装済・2026-08-08・`VLM_OCR_ENABLED` 既定 off / `.env` は on）

`eve/vlm/text_gate.py`（`WindowsOcr` + `ScreenTextGate`）。pHash が「変化なし」の回だけ OCR を
回し、前回テキストとの差分が閾値を超えたら画面認識を起こす。**OCR の読み取りは LLM に一切
渡さない**（外に出るのは bool だけ。public 属性は `available`/`maybe_changed`/`reset` のみ）。

裁定（ユーザ 2026-08-08）:
- **鈍くする**（既定10%）。文章作成中は何十分も文字が増減するので、細かく反応すると実用にならない。
- **pHash 優先**。文字が詰まったタブを閉じると両方が反応する。pHash が変化と言ったらそこで確定し、
  文字ゲートは**見ずに `reset()`**（直後の追い撃ちを防ぐ）。
- 送る枚数は変えない（既存経路のままリングから3枚＝変化前→変化後）。
- OCR 用は別途 PNG/1600 で撮る（送信用 1024/JPEG q70 だと読字が落ちる。送信しないので落とす理由が無い）。

実機E2E `tools/text_gate_e2e.py`（実 API 不要・**2回連続 8/8**）:
① 文字だけ大変化 → **pHash=False のまま文字ゲートが起こす**（この案の存在理由を実証）
② 小さな文字変化 → どちらも起こさない ③ 見た目の大変化 → pHash が起こし文字ゲートは参照されず reset
④ OCR テキストが public に露出しない / 実際に 1200文字読めている

**実起動経路で確認済**（D6）: `tools/voice_chat.py` の起動ログに
`文字ゲート 稼働（ja・10%以上の変化・最短3秒間隔）`。1判定 337ms（grab+OCR+diff 込み）。

#### 文字ゲートの閾値を 25% に（裁定 2026-08-12・実測で決定）

**実測で決めた**（`e2e_logs/full_20260812_1253/pass3_A` と `ocr25_run1`）:

| 閾値 | 作文中(5分) | 通常利用(82分) | 作文中に画面へ言及した自発発話 |
|---|---|---|---|
| 10%（旧） | 3.9 回/分 | 0.51 回/分 | **3件/5分** |
| **25%（採用）** | **0.6 回/分** | 0.34 回/分 | **0件/5分** |
| 30% | 0 回/分 | 0.32 回/分 | — |

30% は作文中を完全に黙らせるが「12行中6行の入れ替え(20.1%)」も見逃すので採らない。
**クールダウンは採らない**（大きな変化が立て続けに起きた時に見逃すため・ユーザ裁定）。

裁定の根拠（ユーザ）: 「Eve を起動している＝基本は会話したい人。本当に集中したいなら起動しない。
静かにしてほしければ『黙って』と言えばよい」。**この前提はコードで裏付けられている**:
`conversation_cache.py:207-221` は、直近窓がイブの発話だけになると**最後のユーザ発話を必ず
アンカーとして付け直す**。実測（オフライン）で自発発話40件を積んでも「黙っててくれる？」は
窓に残り続けた（省略マーカで間の件数を正直に伝えつつ）。ユーザが別の話をすると外れる＝
「もう話していい」の合図として自然。

**動画での検証**（`e2e_logs/video_run1`・2分24秒のアニメ動画を OpenCV の自前窓で再生）:
- 「見えてない」型の言い回し **0件**／動画だと正しく認識／クレジットの文字（「監督 山岸大悟」）まで読めた
- **自発発話は 2回（63秒間隔）**。発話判定は12回起きて喋ったのは2回＝**発話率 17%**
- 停止後「どんな雰囲気だった?」に「落ち着いたアニメのオープニングっぽい雰囲気**だった**よ」と
  **過去形で自然に**答えられた

**保留にした改修（再発したらこれを入れる）**: `context_assembler.py:108` の
`（画面情報なし：今この瞬間の画面は届いていない）` は、性質の違う2つを同じ文言にしている。
(A) 本当に見えていない（capture 死・真っ黒）と (B) **見えていたが実況が追いついていない**
（`state.py:93`）。(B) で「画面が見えてない」と言うと**画面認識が壊れたと誤解される**うえ、
実際には「少し前は見えていた」という情報がある。4つ目の状態
`# 画面（少し前の情報）… N秒前に見えていた内容。そのあと画面は動いているので今は不明`
＋「今の画面として語らない。触れるなら過去形で」を足すのが解。
**閾値25%で症状が出なくなったため今回は入れない**（分岐とプロンプトが増える割に根拠が弱い）。
変化が間欠的かつ大きい状況（タブを何度も切り替える等）で再発したら入れる。

#### 第3弾-1: 起動時/終了時のクリーンアップ（実装済 2026-08-08・`eve/cleanup.py`）

「どんな終わり方をしても次の起動はクリーン」（ユーザ裁定）。**同じ `sweep()` を起動時と終了時の
両方から呼ぶ**＝終了時だけでは異常終了で残り、起動時だけでは稼働中に溜まった物が居座るため。
異常終了で取りこぼした分は次回の起動時掃除が回収する（片方が落ちても収束する）。

掃除するもの: ①未終了タスク（**Running→Failed=やりかけ / Pending→Cancelled=やっていない**と
意味を分ける。1件制では未終了が1件でも残ると次の起動から枠が塞がる）②`.eve_run` の実行残骸
（`winexec.py:248`）③取り残しビューア窓（`DETACHED_PROCESS` なので親が死んでも生き残る。
起動時は Popen ハンドルが無いのでコマンドラインで見つけて畳む）。

**配線順序が本質**（テストで固定した）: 起動時は **executor 起動より前**（後だと reconcile が
前回の Pending を掴んで走り出す）／終了時は **executor 停止後・store 閉鎖前**。

実機E2E `tools/cleanup_e2e.py`（**本番の `tools/voice_chat.py` をそのまま起動**・2回連続 10/10）:
異常終了状態（未終了タスク2件 / `.eve_run` 残骸2件 / ビューア窓2個）を作り `kill` で落としてから
本番起動 → 起動ログに `🧹 起動時の掃除: {'tasks': 1, 'workspace': 2, 'viewers': 1}`、
Pending→Cancelled / Running→Failed / Done は不変 / 残骸0 / 窓0 / **ユーザのファイルは残る**。
（tasks が1なのは `store.initialize()` の孤児処理が先に Running を Failed 化するため＝正常）

#### 第3弾-3: 果たせない約束をさせない（実装済 2026-08-08）

実測（e15_run3・2/2）: 1件制で断る時に「終わったら調べるね」と言うが、**その約束を果たす
仕組みが無い**（依頼はどこにも保存されず、次ターンには文脈から消える）。
原因は**こちらのプロンプトが「終わったらやるね」と言わせていた**こと（1件制導入時に私が書いた）。

修正（プロンプト + 拒否メッセージの両方）: 後回しの約束を禁じ、**「終わったらもう一度言ってね」と
頼ませる**。覚えていられないことは隠さず正直に言ってよい、急ぐなら「今のをやめて先にやろうか?」
と聞く、も明示。ユーザに言い直してもらうのが唯一の確実な引き継ぎ手段。

実測（`e2e_logs/promise_run1..4`・4ラン×2ケース）:
**果たせない約束をしない 8/8** ／ **断ったなら言い直しを頼む 5/5**（断った全ケース）／
同時アクティブのピーク ≤1 が 8/8。実際の発話例:
> いま東京タワーの高さを調べてるところだから、まだ新しい調べ物は受けられないんだ。
> 終わったらもう一度言ってね。急ぐなら、今のをやめて先にスカイツリーを調べようか？

**E2E 判定の作り方の教訓**（2回連続で同じ罠を踏んだ）: 固定 sleep で判定してはいけない。
報告ターンは委譲より後に来るので、発話が止まっただけでも足りない。**パイプラインが静まるまで
待つ**（`_settle_watching_actives`）。また 1件制の不変条件は「同時に1件」であって「2件目を
永久に拒否」ではないため、**新タスクの差分ではなく同時アクティブ数のピーク**で測る
（枠が空いた後に受理されるのは正しい挙動）。

**残る挙動（第4弾=E7 へ送る）**: 断った直後の報告ターンで、その依頼を**自分の記憶で答えて
しまう**（「あと、日本一長い川は信濃川だよ」）。断り方の問題ではなく「推測せず調べる」の領域。

## 6. 落とし穴

1. `$env:PYTHONIOENCODING="utf-8"` を忘れると日本語＋絵文字で落ちる
2. Git Bash の grep は絵文字入りログで壊れる → **Python で解析する**
3. `.env` 変更は再起動が必要（`Config` は構築時に1回だけ読む）。E2E ハーネスは `eve.config` を import する**前**に環境変数を書き換えている＝この順序を崩すと効かない
4. E2E は課金・実画面・メモ帳の自動操作を伴う。VLM 有効時は**実際の画面が Gemini に送られる**
5. 実起動で回すと本番の記憶（`*.jsonl`）が育つ＝D1 の温床
6. `.env` と `*.jsonl` は gitignore＝設定の修正はコミットに残らない
7. **自発発話の効果測定は「件数」で判断しない**。1セッション3-4件しか出ずノイズに埋もれる（条件付き Poisson 検定で p=1.00 の実例あり）。判定回数（数十〜百）を母数にした指標を使う
8. **作業フォルダをユーザプロファイル配下に置くと `run_program` が必ず失敗する**。`C:\Users\<user>` に `BUILTIN\Users` の ACE が無く eve_sandbox から到達できないため（起動時に `exec_compatible` が検出して実行だけ無効化する）。E2E ハーネスも一時ディレクトリを使って実際に踏んだ
9. `wmic` は Windows 11 24H2 以降で**削除済み**。セットアップ系スクリプトで使わない（`Set-LocalUser` 等の PowerShell に寄せる）
10. **`Path.exists()` はアクセス拒否時に False ではなく `PermissionError` を送出する**。「読めないこと」を確かめる検査は try で囲まないと、成功の証拠が例外になって以降の検証を巻き込む
11. J-3 の能力は `.env` に **`WS_ENABLED` / `WS_EXEC_ENABLED` / `WS_VIEWER_ENABLED`** を書かないと丸ごと無効（D6 と同じ構造）。`WS_EXEC` はさらに `setup_sandbox.py apply` 済みが前提
